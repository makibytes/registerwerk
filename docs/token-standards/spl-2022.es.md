# Solana SPL-2022 { #solana-spl-2022 }

**Token-2022** (también conocido como **Token Extensions** o **SPL-2022**) es el programa de tokens de nueva generación de Solana que amplía el programa de tokens clásico SPL con un amplio conjunto de **extensiones** configurables en el momento de la creación del mint. Registerwerk utiliza SPL-2022 para tokens de valor nativos de Solana.

---

## Tipos de tokens admitidos { #supported-token-types }

| Enumeración de tokens | Descripción | Extensiones clave utilizadas |
|---|---|---|
| `SPL` | Token SPL clásico de Solana | Mínimo — solo transferencia estándar |
| `SPL_2022` | Base SPL-2022 | TransferFee, MetadataPointer |
| `SPL_2022_BOND` | Bono con devengo de intereses | InterestBearing, TransferFee, PermanentDelegate |
| `SPL_2022_CONFIDENTIAL` | Token que preserva la privacidad | ConfidentialTransfer, TransferFee |

---

## Extensiones clave de SPL-2022 en uso { #key-spl-2022-extensions-in-use }

### InterestBearing { #interestbearing }

Se utiliza para `SPL_2022_BOND`. Calcula el interés devengado de forma continua a un tipo configurado. El saldo en cadena crece con el tiempo sin necesidad de transacciones de cupón explícitas. `AssetBondTerms.couponRate` se almacena en la configuración de esta extensión en el momento de la creación del mint.

El motor de operaciones societarias lee el interés devengado en las fechas de pago de cupón y lo liquida como un pago aparte para evitar ambigüedades contables.

### ConfidentialTransfer { #confidentialtransfer }

Se utiliza para `SPL_2022_CONFIDENTIAL`. Usa cifrado ElGamal para proteger los importes de las transferencias, y al mismo tiempo permite que la autoridad de acuñación (el operador de Registerwerk) audite todas las transacciones. Esto permite dar privacidad a las posiciones de los inversores manteniendo la supervisión regulatoria.

!!! warning "Se requiere clave pública ElGamal"
    La extensión de transferencia confidencial requiere una clave pública ElGamal para la autoridad de acuñación. Esta clave debe generarse y almacenarse de forma segura antes de implementar un token SPL-2022 confidencial.

### PermanentDelegate { #permanentdelegate }

Se utiliza para `SPL_2022_BOND`. Otorga al monedero del operador de Registerwerk autoridad delegada permanente sobre todas las cuentas de token, lo que permite las operaciones de transferencia forzosa y destrucción forzada exigidas por la autoridad legal del registro conforme al §16 eWpG y a la TVTG.

### TransferFee { #transferfee }

Permite retener una comisión configurable de cada transferencia, enviada a una cuenta de comisiones. Se usa para cobrar automáticamente las tarifas del registro en las transferencias del mercado secundario.

### TransferHook { #transferhook }

Se usa para invocar un programa de Solana personalizado en cada transferencia. En Registerwerk, el programa del transfer hook implementa las comprobaciones de validación del inversor (equivalentes al módulo de cumplimiento de ERC-3643): verifica que la identidad asociada a la cuenta de destino tenga una atestación KYC válida antes de permitir la transferencia.

## Implementación { #deployment }

`SolanaTokenService` gestiona la implementación de SPL-2022:

1. Configura la cuenta mint con las extensiones adecuadas
2. Inicializa la autoridad de acuñación como el monedero de Solana del operador
3. Crea una entrada de registro en `AssetDeployment` con `contractAddress = mintAddress`
4. Para `SPL_2022_BOND`: fija `InterestBearing.rate = couponRate` a partir de `AssetBondTerms`

---

## Indexador { #indexer }

El indexador de Solana (mediante WebSocket de Helius o Shyft) se suscribe a:
- Notificaciones de cambio de cuenta en las direcciones mint rastreadas
- Eventos de transferencia (analizados a partir de los registros de transacciones)
- Eventos de devengo de intereses (para `SPL_2022_BOND`)

Los resultados se escriben en la tabla `token_transfer`, de forma coherente con la salida del indexador de EVM.
