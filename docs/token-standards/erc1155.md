# ERC-1155 — Multi-Token

ERC-1155 allows a single contract to manage multiple token types (both fungible and non-fungible) simultaneously. Each type has its own `id`. Batch operations (batch mint, batch transfer) reduce transaction costs significantly for portfolios with many instruments.

---

## When to use ERC-1155

- **Multi-asset portfolios** — multiple instrument types issued under one programme contract
- **Batch issuance** — large simultaneous allotments (e.g., distribution to 500 investors in a single transaction)
- **Mixed fungible/non-fungible** — some units are fungible (shares), some are unique (certificates)

For single-asset deployments, [ERC-20](erc20.md) or [ERC-3643](erc3643.md) are simpler. ERC-1155 is best suited for programme issuers managing several instruments under a single framework contract.

---

## Token IDs and asset mapping

Each ERC-1155 `tokenId` maps to a separate `Asset` record in Registerwerk. When an operator deploys a multi-token programme:

1. A **programme contract** is deployed (one `AssetDeployment` with `isMultiTokenProgramme = true`)
2. Each instrument in the programme gets its own `tokenId` tracked in `AssetDeployment.tokenId`
3. Balances per investor per token type are tracked in `AssetHolder` with the `tokenId` field

---

## Batch operations

The `Erc1155DeploymentService` exposes batch operations:

| Operation | Description |
|---|---|
| `batchMint(ids[], amounts[], address)` | Mint multiple token types to one address |
| `batchTransfer(ids[], amounts[], from, to)` | Transfer multiple types in one transaction |
| `batchFreeze(addresses[])` | Freeze multiple addresses at once (EwpgERC1155 extension) |

Batch operations reduce gas costs by ~70% compared to sequential single-type operations.
