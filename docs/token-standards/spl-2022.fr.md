# Solana SPL-2022 { #solana-spl-2022 }

**Token-2022** (également connu sous le nom de **Token Extensions** ou **SPL-2022**) est le programme de jetons de nouvelle génération de Solana qui étend le programme de jetons classique SPL avec un riche ensemble d'**extensions** configurables au moment de la création du mint. Registerwerk utilise SPL-2022 pour les jetons de sécurité natifs de Solana.

---

## Types de jetons pris en charge { #supported-token-types }

| Énumération de jetons | Description | Extensions clés utilisées |
|---|---|---|
| `SPL` | Jeton classique Solana SPL | Minimal — transfert standard uniquement |
| `SPL_2022` | Socle SPL-2022 | TransferFee, MetadataPointer |
| `SPL_2022_BOND` | Obligation portant intérêt | InterestBearing, TransferFee, PermanentDelegate |
| `SPL_2022_CONFIDENTIAL` | Jeton préservant la confidentialité | ConfidentialTransfer, TransferFee |

---

## Extensions clés SPL-2022 utilisées { #key-spl-2022-extensions-in-use }

### InterestBearing { #interestbearing }

Utilisé pour `SPL_2022_BOND`. Calcule les intérêts courus en continu à un taux configuré. Le solde en chaîne augmente avec le temps sans nécessiter de transactions de coupons explicites. `AssetBondTerms.couponRate` est stocké dans la configuration de cette extension lors de la création du mint.

Le moteur d'opérations sur titres lit les intérêts courus aux dates de paiement des coupons et les règle comme un paiement distinct pour éviter toute ambiguïté comptable.

### ConfidentialTransfer { #confidentialtransfer }

Utilisé pour `SPL_2022_CONFIDENTIAL`. Utilise le cryptage ElGamal pour protéger les montants des transferts tout en permettant à l'autorité de mint (mint authority, l'opérateur Registerwerk) d'auditer toutes les transactions. Cela permet de protéger la confidentialité des positions des investisseurs tout en maintenant la surveillance réglementaire.

!!! warning "Clé publique ElGamal requise"
    L'extension de transfert confidentiel nécessite une clé publique ElGamal pour l'autorité de mint. Cette clé doit être générée et stockée en toute sécurité avant de déployer un jeton confidentiel SPL-2022.

### PermanentDelegate { #permanentdelegate }

Utilisé pour `SPL_2022_BOND`. Accorde au portefeuille de l'opérateur Registerwerk une autorité déléguée permanente sur tous les comptes de jetons, permettant les opérations de transfert forcé et de destruction forcée (force-burn) requises par l'autorité légale du registre en vertu de l'eWpG §16 et TVTG.

### TransferFee { #transferfee }

Permet de retenir des frais configurables sur chaque transfert, versés vers un compte de perception des frais. Utilisé pour collecter automatiquement les frais d'enregistrement sur les transferts sur le marché secondaire.

### TransferHook { #transferhook }

Utilisé pour appeler un programme Solana personnalisé à chaque transfert. Dans Registerwerk, le programme de transfert implémente des contrôles de validation des investisseurs (équivalents au module de conformité de ERC-3643) : il vérifie que l'identité associée au compte de destination détient un claim KYC valide avant d'autoriser le transfert.

## Déploiement { #deployment }

`SolanaTokenService` gère le déploiement SPL-2022 :

1. Configure le compte Mint avec les extensions appropriées
2. Initialise l'autorité de mint en tant que wallet Solana de l'opérateur
3. Crée une entrée de registre dans `AssetDeployment` avec `contractAddress = mintAddress`
4. Pour `SPL_2022_BOND` : définit `InterestBearing.rate = couponRate` à partir de `AssetBondTerms`

---

## Indexer { #indexer }

L'indexeur Solana (utilisant Helius ou Shyft WebSocket) s'abonne à :
- Notifications de changement de compte sur les adresses de mint suivies
- Événements de transfert (analysés à partir des journaux de transactions)
- Événements d'accumulation d'intérêts (pour `SPL_2022_BOND`)

Les résultats sont écrits dans la table `token_transfer`, conformément à la sortie de l'indexeur EVM.
